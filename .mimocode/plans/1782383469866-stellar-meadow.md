# Plan: Pi Coding Agent + waveterm-remote Integration

## Key Finding

**No changes needed in waveterm-remote.** All APIs pi needs already exist and are battle-tested by the Claude Code integration. pi runs inside a waveterm terminal and has access to `wsh` CLI commands and environment variables.

## 1. Available APIs (waveterm side — no work needed)

### 1a. Tab Badges (`wsh badge`)

Sets icon + color + priority badges on the current block. Badges **auto-clear on focus**, making them ideal for transient signals like "waiting for input."

```
wsh badge <fa-icon> --color <hex> --priority <num> [--beep] [--pid <pid>]
```

**Relevant icons (Font Awesome):**
| Situation | Icon | Color | Priority |
|-----------|------|-------|----------|
| Running/idle | `spinner` | `#00FFDB` | 5 |
| Waiting for user (blocked) | `hourglass-half` | `#FF9500` | 20 |
| Error/abort | `circle-xmark` | `#FF453A` | 25 |
| Success/done | `check` | `#58C142` | 10 |

**How it works under the hood:**
- Publishes a `badge` WPS event scoped to the block
- Frontend `TabBadges` component renders the highest-priority badge on the tab
- `--pid` links badge to a process; auto-clears when PID exits
- Without `--pid`, badge auto-clears when user focuses the block

**Environment context (already set for pi):**
- `WAVETERM_BLOCKID` — `wsh badge` auto-scopes to this block
- `WAVETERM_TABID` — available if pi wants to set tab-level badge explicitly

**Reference:** `cmd/wsh/cmd/wshcmd-badge.go`, `docs/docs/claude-code.mdx`

### 1b. Tab Flag Colors (`wsh setmeta`)

Persistent color flags on tabs (unlike badges, these don't auto-clear on focus).

```
wsh setmeta tab:flagcolor=<color>
```

Available colors: Green `#58C142`, Teal `#00FFDB`, Blue `#429DFF`, Purple `#BF55EC`, Red `#FF453A`, Orange `#FF9500`, Yellow `#FFE900`

Use case: mark the tab as a "pi session" persistently. Combine with badges for transient events.

**Reference:** `frontend/app/tab/tabcontextmenu.ts:10-74`

### 1c. OS Desktop Notifications (`wsh notify`)

Cross-platform desktop notifications via Electron's `Notification` API. Works on **macOS, Windows, Linux**.

```
wsh notify "<body>" -t "<title>" [-s]
```

- `-t` — notification title (default: "Wsh Notify")
- `-s` — silent (no sound)
- 2-second timeout; fire-and-forget

**Implementation:** `emain/emain-wsh.ts:34-40` → `new Notification({ title, body, silent }).show()`

**Cross-platform note:** Electron's Notification API delegates to:
- macOS: Notification Center
- Windows: Action Center / toast notifications
- Linux: libnotify (most DEs), or falls back to Electron's in-app notification

**Reference:** `cmd/wsh/cmd/wshcmd-notify.go`

### 1d. Environment Variables (already passed to pi)

When pi runs inside a waveterm block, the blockcontroller sets these env vars:

| Variable | Value |
|----------|-------|
| `WAVETERM` | `"1"` |
| `TERM_PROGRAM` | `"waveterm"` |
| `WAVETERM_BLOCKID` | Block UUID |
| `WAVETERM_TABID` | Tab UUID |
| `WAVETERM_VERSION` | Version string |
| `WAVETERM_JWT` | JWT for RPC auth |

Pi can check `WAVETERM=1` or `TERM_PROGRAM=waveterm` to conditionally enable the waveterm integration.

**Reference:** `pkg/blockcontroller/blockcontroller.go:587-596`

## 2. Pi-Side Integration (work needed in pi)

### 2a. Hosting

**Public repo**: `codeberg.org/randomingspace/remoteterm-pi-badges` — so anyone can `pi install git:codeberg.org/randomingspace/remoteterm-pi-badges@v1.0.0`.

**Development**: self-hosted Forgejo for private iteration; push to Codeberg for releases.

### 2b. Approach: Pi Extension

An extension keeps the integration self-contained, shareable, and requires no changes to either pi core or waveterm-remote. It follows the same pattern as the image-paste extension (`.pi/specs/pi-image-paste.md`).

**Extension structure:**

```
remoteterm-pi-badges/
├── index.ts          # Extension entry point — subscribe to Agent events
├── package.json      # Extension metadata + peer dependency on pi-agent
└── README.md         # Install + config docs
```

**How it works:**
1. Extension checks `TERM_PROGRAM === "waveterm"` — no-op if not in waveterm
2. Gets a reference to the `Agent` instance (via extension API or DI)
3. Calls `agent.subscribe()` to receive all `AgentEvent` lifecycle events
4. Maps each event to a `wsh badge` / `wsh notify` shell command
5. Spawns `wsh` detached — fire-and-forget, never blocks pi

### 2b. AgentEvent → Badge Mapping

Pi's `Agent` class emits these events (from `packages/agent/src/types.ts`). The extension subscribes via `agent.subscribe()`:

| AgentEvent | When it fires | `wsh badge` call |
|-----------|--------------|-----------------|
| `agent_start` | Processing begins | `wsh badge spinner --color '#00FFDB' --priority 5` |
| `agent_end` (no error) | Run finished successfully | `wsh badge check --color '#58C142' --priority 10` |
| `agent_end` (had error) | Run failed/aborted | `wsh badge circle-xmark --color '#FF453A' --priority 25` |
| `tool_execution_start` (AskUserQuestion) | Waiting for user response | `wsh badge hourglass-half --color '#FF9500' --priority 20 --beep` |
| `tool_execution_start` (other) | Running tools (Bash, Edit, etc.) | `wsh badge gears --color '#429DFF' --priority 8` |
| `tool_execution_end` (isError) | Tool failed | `wsh badge circle-xmark --color '#FF453A' --priority 25` |

Events **NOT** mapped (too granular / too frequent):
- `turn_start`, `turn_end` — a single `prompt()` call can produce many turns (one per tool cycle). Use `agent_end` for the "done" signal.
- `message_start`, `message_update`, `message_end` — fires per token during streaming. Way too noisy.
- `tool_execution_update` — streaming progress from tool execution.

**"Waiting for user input"** is detected by two patterns:
1. `agent_end` fires → pi is idle, waiting for user to type the next prompt
2. `tool_execution_start` with `toolName === "AskUserQuestion"` → pi blocked on user response

### 2c. OS Notification Triggers

OS notifications should only fire when the user may have switched away. Pi can check `Agent.state.isStreaming` — if `false`, the user invoked the app and is watching. If `true` and the user hasn't interacted recently, send a notification.

| Trigger | `wsh notify` call |
|---------|-------------------|
| AskUserQuestion tool fires | `wsh notify "pi needs your input" -t "pi"` |
| Run completes (agent_end) after >30s | `wsh notify "pi finished" -t "pi"` |
| Run errors out | `wsh notify "pi encountered an error" -t "pi"` |

### 2d. Extension Implementation

```typescript
// extensions/waveterm-badges/index.ts
import { defineExtension, type ExtensionAPI } from "@earendil-works/pi-coding-agent";
import type { AgentEvent } from "@earendil-works/pi-agent";
import { spawn } from "child_process";

const isWaveTerm = process.env.TERM_PROGRAM === "waveterm";

function wsh(args: string[]) {
    if (!isWaveTerm) return;
    spawn("wsh", args, { stdio: "ignore", detached: true }).unref();
}

function badge(icon: string, color: string, priority: number, beep = false) {
    const args = ["badge", icon, "--color", color, "--priority", String(priority)];
    if (beep) args.push("--beep");
    wsh(args);
}

function notify(title: string, body: string) {
    wsh(["notify", body, "-t", title]);
}

export default defineExtension((pi: ExtensionAPI) => {
    const agent = pi.agent; // or however pi exposes its Agent instance

    let runStartTime = 0;

    agent.subscribe(async (event: AgentEvent) => {
        switch (event.type) {
            case "agent_start":
                runStartTime = Date.now();
                badge("spinner", "#00FFDB", 5);
                break;

            case "agent_end": {
                const hadError = agent.state.errorMessage != null;
                if (hadError) {
                    badge("circle-xmark", "#FF453A", 25);
                    notify("pi", "pi encountered an error");
                } else {
                    badge("check", "#58C142", 10);
                    if (Date.now() - runStartTime > 30000) {
                        notify("pi", "pi finished");
                    }
                }
                break;
            }

            case "tool_execution_start":
                if (event.toolName === "AskUserQuestion") {
                    badge("hourglass-half", "#FF9500", 20, true);
                    notify("pi", "pi needs your input");
                } else {
                    badge("gears", "#429DFF", 8);
                }
                break;

            case "tool_execution_end":
                if (event.isError) {
                    badge("circle-xmark", "#FF453A", 25);
                }
                break;
        }
    });
});
```

## 3. Extension Configuration

Users should be able to customize badge icons/colors/priorities and notification text without editing the extension code. A simple config approach:

```jsonc
// In pi's settings
{
  "extensions": {
    "waveterm-badges": {
      "badges": {
        "running":   { "icon": "spinner",         "color": "#00FFDB", "priority": 5 },
        "tooling":   { "icon": "gears",            "color": "#429DFF", "priority": 8 },
        "waiting":   { "icon": "hourglass-half",   "color": "#FF9500", "priority": 20, "beep": true },
        "done":      { "icon": "check",            "color": "#58C142", "priority": 10 },
        "error":     { "icon": "circle-xmark",     "color": "#FF453A", "priority": 25 }
      },
      "notifications": {
        "enabled": true,
        "minRunDurationMs": 30000  // only notify for runs longer than 30s
      }
    }
  }
}
```

## 4. Recommended waveterm-remote Enhancement: Icon Rotation

Animated gear rotation tied to `turn_end` gives continuous visual feedback that pi is making progress. Each turn advances the gear by 30°, with a 0.1s CSS transition for smooth interpolation.

### 4a. Changes needed (`pkg/baseds/baseds.go`)

Add a `Rotation` field to the `Badge` struct:

```go
type Badge struct {
    BadgeId   string  `json:"badgeid"`
    Icon      string  `json:"icon"`
    Color     string  `json:"color,omitempty"`
    Priority  float64 `json:"priority"`
    PidLinked bool    `json:"pidlinked,omitempty"`
    Rotation  float64 `json:"rotation,omitempty"`  // NEW: degrees 0-360, applied via CSS transform
}
```

### 4b. Changes needed (`frontend/types/gotypes.d.ts`)

```typescript
type Badge = {
    badgeid: string;
    icon: string;
    color?: string;
    priority: number;
    pidlinked?: boolean;
    rotation?: number;  // NEW
};
```

### 4c. Changes needed (`frontend/app/tab/tabbadges.tsx`)

In the `<i>` element rendering, apply `transform` with `transition` when `rotation` is set:

```tsx
<i
    key={badge.badgeid}
    className={`fa-sharp fa-solid fa-${badge.icon}`}
    style={{
        color: badge.color,
        ...(badge.rotation != null ? {
            transform: `rotate(${badge.rotation}deg)`,
            transition: "transform 0.1s ease",
        } : {}),
    }}
/>
```

Also render in `blockframe-header.tsx:287` (block-level badges use the same icon rendering).

### 4d. Changes needed (`cmd/wsh/cmd/wshcmd-badge.go`)

Add `--rotation` flag:

```go
var badgeRotation float64

func init() {
    badgeCmd.Flags().Float64Var(&badgeRotation, "rotation", 0, "icon rotation in degrees (0-360)")
}
```

In `badgeRun`, set `eventData.Badge.Rotation = badgeRotation` when the flag is provided and non-zero.

### 4e. Extension usage

```typescript
const ROTATION_STEP = 30; // 12 frames per full rotation
let rotation = 0;

agent.subscribe(async (event) => {
    switch (event.type) {
        case "agent_start":
            rotation = 0;
            badge("gear", "#00FFDB", 5, { rotation: 0 });
            break;

        case "turn_end":
            if (event.toolResults.length > 0) {
                rotation = (rotation + ROTATION_STEP) % 360;
                badge("gear", "#00FFDB", 5, { rotation });
            }
            break;

        case "agent_end":
            badge("check", "#58C142", 10);
            break;
    }
});
```

`wsh badge` call: `wsh badge gear --color '#00FFDB' --priority 5 --rotation 30`

### Why no glitchiness

- Badge icon is a square glyph — rotation doesn't shift layout
- CSS `transition: 0.1s ease` interpolates from old angle to new, no snap
- Each `wsh badge` call replaces the previous badge atom for that oref — single source of truth
- React sees the new `rotation` value and triggers the transition naturally
