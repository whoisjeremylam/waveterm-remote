# Root Cause Analysis: Untracked File Click Shows Blank in Source Control Widget

## Request
Investigate why clicking an untracked file in the source control widget displays blank instead of the file content.

## Code Flow Summary

The SCM widget lives on `origin/feature/source-control-widget` (not yet on `main`).

```
User clicks untracked file 
  → handleFileSelect({path, staged: false, untracked: true})       [sourcecontrol.tsx:285]
  → sets model.selectedFileAtom                                     [sourcecontrol.tsx:165]
  → Jotai subscription fires                                        [sourcecontrol-model.ts:102]
  → fetchDiffForSelected()                                          [sourcecontrol-model.ts:192]
  → reads cwd atom + selected atom, calls fetchDiff(cwd, path, staged, untracked)  [sourcecontrol-model.ts:200]
  → RPC: GitDiffCommand({dir, path, staged, untracked}, {route})    [sourcecontrol-model.ts:186]
  → Backend: ServerImpl.GitDiffCommand()                            [pkg/wshrpc/wshremote/git.go:83]
    → if untracked: os.ReadFile(filepath.Join(dir, path))           [git.go:108]
    → if tracked:  git diff [--cached] -- <path>                    [git.go:120-124]
  → Returns {original, modified, language} or error
  → Frontend sets diffAtom → DiffPanel renders MonacoDiffViewer
```

## Root Cause Analysis

### Primary Issue: CWD Desynchronization (Race Condition)

The `cwd` atom in `sourcecontrol-model.ts` is a **derived** atom that changes dynamically when:
1. The user focuses a different terminal (which drives `terminalCwd`)
2. The user selects a custom directory via the DirectoryDropdown (`userCwd`)

**The bug**: `fetchStatus()` (the 3-second poll) reads `cwd` at time T1, and `fetchDiffForSelected()` reads `cwd` again at time T2 (when the user clicks). If the CWD has changed between T1 and T2, the diff fetch uses a **different directory** than the git status poll did.

```
T1 (poll):     cwd = /repo/subdir/    → git status runs here, returns files relative to subdir/
T2 (click):    cwd = /repo/           → fetchDiff uses /repo/ instead of /repo/subdir/
                path = "file.txt"     → filepath.Join("/repo/", "file.txt") ≠ "/repo/subdir/file.txt"
                os.ReadFile fails     → error → diffAtom = null → "blank" display
```

For **tracked files**, this is partially masked because `git diff -- <file>` with `cmd.Dir = /repo/` still resolves paths from the repo root. For **untracked files**, the manual `os.ReadFile` produces a wrong path.

### Secondary Issue: Missing Go Dispatch?

The `WshRpcInterface` declares `GitStatusCommand` and `GitDiffCommand`, but the main `WshServer` struct (`pkg/wshrpc/wshserver/wshserver.go`) does not implement them. The actual implementation lives on `*ServerImpl` in `pkg/wshrpc/wshremote/git.go`. The RPC system likely uses reflection-based dispatch through the WshRouter (routing based on `route: conn:<name>` or `route: wavesrv`), but this needs verification. If the RPC routing isn't properly wiring up git commands to the remote server, the calls would silently fail.

### Tertiary: `"~"` Fallback

When `terminalCwd` and `userCwd` are both empty, `cwd` falls back to the literal string `"~"`. Go's `os.ReadFile("~/file.txt")` does **not** expand tilde — it would try to open a directory literally named `~`.

### Real Production Logs Analysis (after user applied logging)

```
[SCM] fetchDiffForSelected: cwd="/home/.../waveterm-remote-vcs" path="package-lock.json" staged=false untracked=false
  → diff result: hasOriginal=true, hasModified=true, modifiedLen=303  ✅ Works

[SCM] fetchDiffForSelected: cwd="/home/.../waveterm-remote-vcs" path=".mimocode/" staged=false untracked=true
  → diff result: hasOriginal=false, hasModified=false, modifiedLen=0   ❌ Empty

[SCM] fetchDiffForSelected: cwd="/home/.../waveterm-remote-vcs" path="golang-1.26.2" staged=false untracked=true
  → diff result: hasOriginal=false, hasModified=false, modifiedLen=0   ❌ Empty
```

The empty result with `language:"plaintext"` and NO error is exactly what `git diff -- .mimocode/` (tracked branch) produces for an untracked directory. This means `data.Untracked` arrived as `false` in Go.

The working theory: the **`untracked: true` flag is lost during RPC serialization** (JS → JSON → Go `map[string]interface{}` → `json.Marshal` → `CommandGitDiffData`). Log #5 will confirm this definitively.

The CWD mismatch theory is ruled out — all three calls use the same CWD.

### What to Look For

After adding log #5, reproduce the bug and check the backend output:
- If it shows `untracked=false` → **serialization bug confirmed**; investigate `ReUnmarshal` / JSON round-trip
- If it shows `untracked=true` → something else wrong; check `os.ReadFile` error path, `filepath.Join` result

## Recommended Fix

Store the CWD used for the last git status fetch in a separate atom or instance variable, and **reuse that same CWD** in `fetchDiffForSelected`:

```tsx
// In SourceControlViewModel:
lastStatusCwd: string = "";

async fetchStatus() {
    const cwd = globalStore.get(this.cwd);
    this.lastStatusCwd = cwd;  // remember the CWD used for this poll
    // ... rest of fetchStatus
}

async fetchDiffForSelected() {
    const selected = globalStore.get(this.selectedFileAtom);
    // Use the CWD from the last status fetch, not the current cwd atom:
    const cwd = this.lastStatusCwd || globalStore.get(this.cwd);
    // ... rest of fetchDiffForSelected
}
```
