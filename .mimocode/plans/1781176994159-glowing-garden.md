# Fix: Header Icons (close, settings, magnify, reload) Intermittently Don't Respond to Clicks

## Root Cause

**Primary: `useLongClick` hook has a non-reactive `ref.current` dependency**

The `useEffect` in `useLongClick.tsx:56` depends on `[ref.current, startPress, stopPress, handleClick]`. `ref.current` is a mutable ref property, **not React state**. On first render, `ref.current` is `null`. The effect runs, sees `null`, early-returns, attaches **zero listeners**. When React assigns the ref after commit, `ref.current` becomes the DOM element — but no re-render is triggered, so the effect never re-runs. The button ends up with **no click handlers at all**.

The bug is intermittent because if *anything* causes a re-render after mount (atom change, focus toggle, metadata update), the effect re-runs with the now-populated `ref.current` and listeners attach successfully. On blocks where atoms stay stable, listeners never attach.

**Evidence**: All header icons (close, settings, magnify, reload, split) are affected — they all use `IconButton` → `useLongClick`. The webview compositing issue is secondary and only applies to the close button specifically.

**Secondary: Electron `<webview>` compositing layer can intercept pointer events**

The `<webview>` tag creates a guest-view compositor layer (`webview.scss:18-19`) that can steal clicks. Even with listeners attached, the close button may not work on webview blocks. This is a separate, lower-priority issue.

## Fix 1: Fix `useLongClick` ref.current dependency (primary)

**File**: `frontend/app/hook/useLongClick.tsx`

Replace `ref.current` in the dependency array with a `mounted` state flag that transitions `false → true` after the first commit, ensuring the listener-attachment effect re-runs when the ref is available:

```tsx
const [mounted, setMounted] = useState(false);
useEffect(() => { setMounted(true); }, []);

// Change dependency from [ref.current, startPress, stopPress, handleClick]
// to [disabled, startPress, stopPress, handleClick, mounted]
```

**Risk**: Low. One-shot state trigger ensures listeners attach on first render. Behavior for already-mounted elements is unchanged.

## Fix 2: CSS stacking context on header (secondary — webview-specific)

**File**: `frontend/app/block/block.scss:77`

Add `position: relative; z-index: 1;` to `.block-frame-default-header`. Forces the header into its own compositing layer above the webview's layer, so pointer events reach the header even when the webview's compositor is active.

```scss
.block-frame-default-header {
    ...
    position: relative;
    z-index: 1;
```

**Risk**: Low. `position: relative` on a flex item doesn't change layout. `z-index: 1` is well below block-mask (10) and header-hover (100).
