# Image Rendering Support for WaveTerm + pi

## Context

pi-tui already has full image encoding (Kitty + iTerm2) and an `Image` component. WaveTerm uses xterm.js v6 but lacks image decoding. Once WaveTerm adds `@xterm/addon-image` and pi-tui adds WaveTerm detection, images will render automatically.

## Changes

### 1. WaveTerm: Add `@xterm/addon-image`

**`package.json`** - Add dependency:
```bash
npm install @xterm/addon-image
```

**`frontend/app/view/term/termwrap.ts`** - Load addon in constructor (after line 161):
```typescript
import { ImageAddon } from "@xterm/addon-image";

// After other addon loads:
const imageAddon = new ImageAddon({
  sixelSupport: true,
  kittySupport: true,
  iipSupport: true,
  enableSizeReports: true,
});
this.terminal.loadAddon(imageAddon);
```

### 2. pi-tui: Add WaveTerm Detection

**`packages/tui/src/terminal-image.ts`** in `detectCapabilities()` (after iTerm2 check):
```typescript
if (termProgram === "waveterm") {
  return { images: "kitty", trueColor: true, hyperlinks: true };
}
```

### 3. Tests

**pi-tui test** (`packages/tui/test/terminal-image.test.ts`):
- Test `detectCapabilities()` returns `images: "kitty"` for `TERM_PROGRAM=waveterm`
- Test `encodeKitty()` produces valid escape sequences
- Test `encodeITerm2()` produces valid escape sequences
- Test `getImageDimensions()` parses PNG/JPEG/GIF/WebP

**WaveTerm test** (`frontend/test/image-addon.test.ts`):
- Test `ImageAddon` loads without errors
- Test addon options are configured correctly
