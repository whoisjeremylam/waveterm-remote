# Bug Fix: Terminal Resize for Background Sessions (tmux)

## Problem Statement

When the waveterm window is resized while a tab is in the background (inactive), terminal sessions (including tmux) don't receive the new size. When switching to that tab, the terminal has black areas because it's still at the old size.

## Root Cause

Each tab is a separate Electron `WebContentsView`. When inactive, tabs are positioned off-screen at (-15000, -15000) but maintain their width/height. When the window resizes:

1. `positionTabOffScreen(winBounds)` calls `setBounds({x: -15000, y: -15000, width: newWidth, height: newHeight})`
2. The browser optimizes layout for off-screen content, so `ResizeObserver` may not fire
3. When the tab is later moved on-screen (position changes from (-15000,-15000) to (0,0)), `ResizeObserver` doesn't fire because it only observes **size** changes, not position changes
4. The terminal stays at the old size, causing black areas

## Solution

Add an explicit `wave-resize` IPC channel from main→renderer, triggered on:
- **Tab switch**: Send resize signal to newly active tab after positioning
- **Window resize**: Send resize signal to all inactive tabs (debounced 200ms)

## Implementation (6 files, +31 lines)

### 1. `emain/preload.ts` (line 69)
Add IPC callback bridge:
```typescript
onWaveResize: (callback) => ipcRenderer.on("wave-resize", (_event) => callback()),
```

### 2. `emain/emain-window.ts` (lines 252-265)
Add debounced handler for inactive tabs on window resize:
```typescript
const notifyInactiveTabsResize = debounce(200, () => {
    if (this.isDestroyed()) { return; }
    for (const tabView of this.allLoadedTabViews.values()) {
        if (tabView === this.activeTabView) { continue; }
        if (tabView?.webContents && !tabView.webContents.isDestroyed()) {
            tabView.webContents.send("wave-resize");
        }
    }
});
this.on("resize", notifyInactiveTabsResize);
```

```typescript
React.useEffect(() => {
    const handleWaveResize = () => {
        model.termRef.current?.handleResize();
    };
    window.addEventListener("wave-resize", handleWaveResize);
    return () => {
        window.removeEventListener("wave-resize", handleWaveResize);
    };
}, []);
```

## Why This Works

1. **Tab switch**: `setTabViewIntoWindow()` positions the tab on-screen via `finalizePositioning()`, then explicitly sends `wave-resize` to ensure the terminal resizes
2. **Window resize (inactive tabs)**: The 200ms debounced handler iterates all inactive tabs and sends `wave-resize` to each, bypassing the unreliable `ResizeObserver` for off-screen content
3. **Minimal overhead**: `handleResize()` already checks if `cols`/`rows` actually changed before sending `ControllerInputCommand` to the backend, so redundant calls are cheap
