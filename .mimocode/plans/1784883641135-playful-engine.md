# Fix: + New Tab dropdown only shows local host

## Bug

After implementing frecency sort + filtering (commit `8024da00`), the "+ New Tab" dropdown only shows the local host entry and no remote connections.

## Root Cause

`frontend/app/tab/connectiondropdown.tsx:77-80` wraps `ConnListCommand` and `WslListCommand` in `Promise.all`:

```ts
const [connResult, wslResult] = await Promise.all([
    RpcApi.ConnListCommand(TabRpcClient, { timeout: 2000 }),
    RpcApi.WslListCommand(TabRpcClient, { timeout: 2000 }),
]);
```

`Promise.all` fails-fast — if `WslListCommand` rejects (which it does on non-Windows systems where WSL is unavailable), the entire `Promise.all` rejects. `connResult` is never assigned, `connList` stays `[]`, and only the local host appears.

The old working code in `conntypeahead.tsx:166-181` calls both RPCs independently with separate `.catch()` handlers, so WSL failure doesn't block the connections list.

## Fix

Replace `Promise.all` with two independent promise chains (matching the `conntypeahead.tsx` pattern) so `WslListCommand` failure doesn't prevent `ConnListCommand` results from being set.

### File: `frontend/app/tab/connectiondropdown.tsx`

Replace lines 76-83:

```ts
const [connResult, wslResult] = await Promise.all([
    RpcApi.ConnListCommand(TabRpcClient, { timeout: 2000 }),
    RpcApi.WslListCommand(TabRpcClient, { timeout: 2000 }),
]);
setConnList(connResult || []);
setWslList(wslResult || []);
```

With:

```ts
try {
    const connResult = await RpcApi.ConnListCommand(TabRpcClient, { timeout: 2000 });
    setConnList(connResult || []);
} catch (e) {
    console.error("Failed to load connections:", e);
}
try {
    const wslResult = await RpcApi.WslListCommand(TabRpcClient, { timeout: 2000 });
    setWslList(wslResult || []);
} catch (e) {
    // WSL not available on non-Windows systems — fail silently
}
```

The outer `try/finally` for `setLoading(false)` is already in place and will still execute.

## Verification

1. Run `npx vitest run frontend/app/modals/conn-suggestions.test.ts` (the unit tests for `buildNewTabSuggestions` should still pass since they test the pure function, not the fetch logic)
2. Run `task dev` and verify the dropdown shows remote connections (on Linux, where WSL doesn't exist, the bug was 100% reproducible)
3. Check the browser console: the "Failed to load connections" error should NOT appear; only a silent WSL failure is expected
